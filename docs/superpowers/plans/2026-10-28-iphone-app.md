# verder for iPhone — Plan 1: toolchain, sign-in, snap → ingest

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Martin snaps a paper letter on his iPhone 16 Pro. It appears in verder's Files, gets OCR'd and named, and produces suggestions, the same as a scan from the upstairs scanner.

**Architecture:**
- **The app.** A native SwiftUI app in `apps/ios/`, with the Xcode project generated by XcodeGen.
- **Sign-in.** The app signs in with the session cookie better-auth already issues. A password or a native passkey produces that cookie, which the app keeps in the Keychain and sends itself. There is no bearer plugin and no change to better-auth's session handling.
- **Upload.** Pages are cleaned on the phone, packed into one PDF, and queued in the App Group. A background `URLSession` sends each PDF to a new idempotent `POST /api/mobile/v1/documents`.
- **Ingest.** After upload, the existing `docmeta.sweep` OCRs, names and suggests. Nothing new is needed.

**Tech Stack:** Swift 6 / SwiftUI, iOS 26, VisionKit, Core Image, PDFKit, AuthenticationServices, LocalAuthentication, Swift Testing, XcodeGen; Next 15 route handlers, vitest, drizzle migrations.

**Spec:** `docs/superpowers/specs/2026-10-28-iphone-app-design.md`. This plan covers spec §10 slices 1–3. Slices 4–8 (APNs, proposals, Voor jou, auto-filing, extras) get Plan 2 and Plan 3, written after this one ships, because the session mechanism and the measured upload sizes feed them.

## Global Constraints

- iPhone only, portrait, deployment target **iOS 27.0** (Martin's phone runs 27.2, measured 2026-10-28; Team ID 7RKC7FRL24). Bundle id **`pro.vanderpoel.verder`**, App Group **`group.pro.vanderpoel.verder`**.
- Development signing with Martin's paid team. Install on his iPhone 16 Pro only (devicectl id `4151AD85-3F8B-5DE7-9B5F-CCD2534206A5`). Never the App Store.
- The production origin is `https://verder.vanderpoel.pro`, and it is the passkey RP ID.
- The app UI is Dutch. Code, comments and commits are English.
- No third-party Swift dependencies unless one is measured as necessary (XcodeGen is a build tool, not a dependency).
- The Holodek tokens are ported one-to-one from `apps/web/src/app/globals.css`. **Amber (`attn`) is only for what is waiting on Martin.** Saira and IBM Plex Mono are bundled. Dark only.
- The session credential lives in the Keychain with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`.
- Every route validates the session BEFORE reading the body (as `apps/web/src/app/api/upload/route.ts` does).
- Every migration is applied from the homelab HOST before the new web/worker images. The rsync uses CLAUDE.md's exact exclude list, with `--dry-run --info=del` first and every `deleting` line read.
- Run builds/tests with `env -u NODE_ENV`. Run `next build` locally before any deploy that touches a `packages/api` type.
- Cold launch to a live camera under **2 s**. PDF target under **1.5 MB per page**. The upload ceiling is `MAX_UPLOAD_BYTES` = 50 MB.
- Times reported to Martin are in Europe/Amsterdam.

## Review Focus

1. **Retry after a lost response.** The server stored the PDF but the phone never saw the 200, so it retries with the same `clientId`. Expected: one document, not two (Task 9 test `same clientId twice yields one document`).
2. **Session expired while items are queued.** Expected: a 401 leaves items `pending` rather than `failed`, the app asks for sign-in once, and the queue drains afterwards (Task 11 test `401 keeps item pending and raises signInRequired`).
3. **Phone offline, app killed, phone rebooted.** Expected: the queue survives on disk and drains when the network returns (Task 11 test `queue reloads persisted items`).
4. **A long letter (20 pages).** Expected: it stays well under 50 MB and is not rejected (Task 10 test `twenty pages stay under 30 MB`).
5. **The Cloudflare WAF limit (10/min/IP on `/api/auth/*`) answers 429.** Expected: the app shows "Even wachten — te veel pogingen. Probeer het over een minuut opnieuw." and does not retry in a loop (Task 5 test `429 maps to rateLimited`).
