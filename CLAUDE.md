Regenerate the workbook fixtures with `node packages/parsers/fixtures/make-sheet-fixtures.mjs`. Junk-document discard NOT YET DEPLOYED as of 2026-08-20 — migration 0021 is UNAPPLIED in production and the backfill is UNRUN; apply `pnpm --filter @verder/db migrate` from the homelab HOST BEFORE the new web/worker images go up, or every Discard click 500s on `invalid input value for enum doc_status` with the ledger event already written (migration 0021, additive `doc_status` value `discarded`): `gmail-auth.ts` no longer promotes message parts that are `Content-Disposition: inline` AND carry a `Content-ID` (the `cid:` images an HTML body embeds), which were 56% of all filed attachments; the decision is the pure `isInlineBodyImage` in `apps/worker/src/gmail-parts.ts`, and a part with malformed headers is KEPT, never skipped. Discard is a third `doc_status`, appended through `document_status_changes` with its ledger event — never a delete, because `documents` is append-only and already carries a `document.ingested` event. THE TRAP: discard is never written back to `documents.status`, which reads `"inbox"` forever, so every filter must resolve the effective status via `effectiveDocument` — the surfaces that do are `documents.list` (default-excludes, filtered in SQL BEFORE the LIMIT so discarded rows cannot eat an evidence picker's page budget; `includeDiscarded: true` opts in), `suggestions.list`, `dashboard.stats.pendingSuggestions`, `suggestions.approveEntry` (`proposed.attachmentDocumentIds` is an INGEST-TIME snapshot and is re-resolved at approval, or a discarded logo lands back in `entry_documents` and in the signed export), `search/retrieve.ts` and `search/recent.ts` (the ⌘K palette's empty state, which a discard's reindex would otherwise push to position #1). A SECOND trap under it: `search_chunks.status` is denormalized per chunk and the status renders into the TOP of the body only, so on a multi-chunk document only chunk 0's `source_hash` changes — `indexEntity` therefore refreshes status/occurred_at on text-unchanged chunks WITHOUT re-embedding them, otherwise chunks 1..n keep a stale status and one of them is enough to resurrect the document in search. `document.updated` is recomputed from the live `document_status_changes` row by `resolveDocumentUpdatedHashes` in `verification.ts` (matched rows are CONSUMED, so an identical duplicate cannot vouch for two events) — without it an UPDATE on that table hides a document from every surface while /verify reports ok. Search filters with `IS DISTINCT FROM 'discarded'`, not `<>`: `NULL <> 'discarded'` is NULL and would drop every entity type that has no status. Vault bytes are NEVER purged: it would reclaim ~1% of the vault, the image stays inside the archived `.eml` anyway, and it would teach `nightly-verify` that some missing files are acceptable. "Always discard" needs no rule table — `ingestDocument` dedups on sha256, so a discarded document stays discarded for those bytes forever. Backfill the ones already filed with `pnpm --filter worker discard-signature-images` (idempotent; matches `source='email-attachment' AND title='image.png' AND created_at < 2026-08-21`, because the disposition header is gone post-hoc and `image.png` is also what a pasted-from-clipboard screenshot is called; only documents still in the inbox are touched, so a `filed` judgement always wins; one ledger event each, each individually undoable). The Gmail port skip requires `image/*` mime AND inline AND a `Content-ID`: macOS/iOS Mail marks EVERY attachment inline with a Content-Id, so disposition alone would drop a mailed Beschikking.pdf unrecoverably (pollGmail short-circuits on a seen message id). Every skipped part is written into the `gmail` worker run. Nightly dump now excludes `search_chunks` data, so a restore is only correct if it ends in `pnpm --filter worker reindex` (flags `--entity= --since= --prune`; there is no env-var form). Text extraction for documents ingested before the feature: `pnpm --filter worker extract-texts` (idempotent; also retries anything stored as extractor `none` on a mime extraction might now handle — PDFs, images, both spreadsheet mimes, and the uninformative ones like `application/octet-stream`, which is what ABN's export is recorded as). NOTE: `retrieval-eval` must run from the homelab HOST, not inside the worker container — its CREATE/DROP DATABASE guard only permits localhost, and inside the container the DB host is `postgres`.

## Project laws
- Evidence tables are append-only (enforced by Postgres grants); every evidence mutation appends a `ledger_events` row in the same transaction. Never weaken this.
- AI output is suggestion-only; nothing enters the ledger without Martin's approval. Model suggestion + verdict + edit diff are always recorded (golden rule: self-improvement).
- Tone: supportive/encouraging toward Martin; short, professional, official register for anyone else.
