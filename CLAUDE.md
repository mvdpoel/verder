Search filters with `IS DISTINCT FROM 'discarded'`, not `<>`: `NULL <> 'discarded'` is NULL and would drop every entity type that has no status. Vault bytes are NEVER purged: it would reclaim ~1% of the vault, the image stays inside the archived `.eml` anyway, and it would teach `nightly-verify` that some missing files are acceptable. "Always discard" needs no rule table — `ingestDocument` dedups on sha256, so a discarded document stays discarded for those bytes forever. Statement coverage is inferred from each statement's first and last booking, computed in AMSTERDAM CALENDAR DAYS with abutting statements MERGED — a June exported as 1–15 plus 16–30 abuts rather than overlaps, and an overlap-only merge hatched a month every row of which is present, while UTC-instant arithmetic disagreed with `monthKey` by the offset — and it understates a quiet month on purpose: a month that is not provably complete renders hatched, and a month with no rows renders `geen data`, never €0. `money.month` reads a SQL window TWO DAYS WIDER than the month on each side and still pairs the exact month with `monthKey` in JS: month membership is an Amsterdam question, so an exact UTC window would drop the boundary rows the JS filter has to judge — widen the SQL, decide in JS. A parse-error row inherits the statement's account when every readable row in that file names the same one, and takes that import's EARLIEST readable booking rather than `new Date()`, or one unreadable line invents a permanent hatched "onbekende rekening" card on /money, dated today, forever. ## Project laws
- Evidence tables are append-only (enforced by Postgres grants); every evidence mutation appends a `ledger_events` row in the same transaction. Never weaken this.
- AI output is suggestion-only; nothing enters the ledger without Martin's approval. Model suggestion + verdict + edit diff are always recorded (golden rule: self-improvement).
- Tone: supportive/encouraging toward Martin; short, professional, official register for anyone else.
